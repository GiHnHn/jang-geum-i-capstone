# 개발 이력과 코드 구분

장금이는 개발 과정에서 사용 흐름을 바꿨습니다. 초기에는 사진이나 검색어로 레시피를 조회하고 별도 화면에서 재료를 찾는 기능을 만들었습니다. 최종적으로는 **캐릭터와 대화로 레시피를 정하고 필요한 재료를 추천받은 뒤, 음성으로 조리하는 방식**으로 구성했습니다.

## 최종 서비스 흐름

1. 캐릭터를 선택하고 메신저형 대화창을 엽니다.
2. n8n을 통해 질문과 답변을 주고받으며 레시피를 확인합니다. 재료 구매를 요청하면 `naver_shopping` 도구로 상품을 추천합니다.
3. '이 레시피로 요리하기'를 눌러 레시피를 조리 화면으로 가져갑니다.
4. 조리 중에는 음성으로 질문하고 캐릭터 음성으로 안내받습니다.

## 초기 구현으로 남긴 기능

| 기능 | 관련 코드 | 현재 문서에서의 구분 |
|---|---|---|
| 음식 사진 업로드 후 GPT API로 레시피 조회 | `MainApp.js`의 사진 입력, `server.js`의 `/upload` 내 `imageUrl` 처리 분기, Firebase 설정 | 초기 레시피 탐색 방식. 최종 메신저형 대화의 구조도에서는 제외 |
| 별도 화면에서 검색어로 레시피 조회 | `MainApp.js`의 직접 검색 UI | 초기 조회 화면. n8n 대화창과 구분 |
| 별도 구매 화면의 재료 검색 | `PurchasePage.js`, `server.js`의 `/api/search`, Naver API 설정 | 초기 별도 화면. 최종 채팅에서 사용하는 n8n의 `naver_shopping` 도구와 구분 |

## 초기 파일에서 계속 사용하는 부분

파일 전체가 같은 시기의 기능으로만 구성되어 있지는 않습니다.

- [ChatUI.jsx](../front/src/components/ChatUI.jsx)는 n8n 대화와 '요리하기' 버튼을 구현한 파일입니다.
- [MainApp.js](../front/src/components/MainApp.js)는 사진·직접 검색 UI와 함께, 대화에서 전달받은 `recipeText`를 `/upload`의 텍스트 처리로 구조화한 뒤 조리 화면으로 넘기는 코드도 포함합니다. 따라서 파일 전체를 미사용으로 분류하지 않았습니다.
- [CookingAssistant.js](../front/src/components/CookingAssistant.js)의 음성 입력, `/assistant` 질문 처리, `/tts` 음성 재생은 조리 흐름을 이해할 때 참고할 부분입니다.

n8n의 `naver_shopping`은 최종 채팅에서 재료 구매 요청에 응답하는 도구로 사용했습니다.

n8n 구성은 [개발 당시 스크린샷](images/n8n-workflow.png)으로 확인할 수 있습니다. 실행용 워크플로우 JSON과 음성 모델 실행 환경은 저장소에 포함하지 않았으므로, 보관된 웹 코드만으로 당시 외부 환경 전체를 재현할 수는 없습니다.

## 공개용 문서 정리

최종 서비스 설명에는 메신저형 대화와 음성 조리를 우선 담았습니다. 초기 기능은 개발 이력으로 구분하고, 기존 코드는 그대로 보관했습니다. API와 화면 파일의 존재 여부만으로 최종 사용 기능을 판단하지 않도록 이 문서를 함께 남깁니다.
